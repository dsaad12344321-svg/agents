# Contributing

## Adding or updating an agent
- Keep one agent per agents/<agent-id>/SKILL.md.
- Preserve a distinct role, point of view, responsibilities, workflow, deliverables, rules, and collaboration boundaries.
- Avoid duplicating another agent's mandate.
- Add evidence standards and explicitly prohibit fabricated research or outcomes.
- Update the agent table in README.md when adding or renaming an agent.

## Agent quality checklist
- [ ] Mission is specific and non-overlapping.
- [ ] Independent point of view is explicit.
- [ ] Workflow is actionable.
- [ ] Deliverables are concrete.
- [ ] Constraints and failure modes are documented.
- [ ] Collaboration handoffs are named.
- [ ] Accessibility, privacy, and evidence integrity are considered.

## Team workflow changes
Changes to orchestration must preserve independent opinions, structured disagreement, an explicit decision log, and clear decision rights. Do not make the team automatically agree or let a single agent silently overwrite another agent's conclusion.

## Writing style
Use direct language, observable criteria, and testable outcomes. Mark assumptions as assumptions. Do not include fabricated success metrics or claim that a workflow is implemented in software unless it actually is.
